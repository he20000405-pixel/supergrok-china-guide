# Grok Automations 怎么用？定时任务、邮件触发器与通知设置

**直接结论：**打开 [grok.com/automations](https://grok.com/automations)，先创建一个内容简单的定时任务，再用 `Run now` 手动测试。确认结果正确后，才让它按计划持续运行。

xAI 官方说明，**定时 Automations 对所有 Grok 用户开放，邮件触发器属于 SuperGrok 权益**。如果你只想每天生成一次新闻摘要，不需要先购买 SuperGrok；如果你希望收到特定邮件后自动执行任务，才需要核对 SuperGrok 订阅和邮箱连接权限。

**English summary:** Grok Automations can run once or on a recurring schedule. Scheduled automations are available to all users, while email-triggered automations are included with SuperGrok.

**关键词：** `Grok Automations` · `Grok 定时任务` · `Grok 自动化` · `Grok 邮件触发器` · `SuperGrok Automations`

## 先判断你需要哪一种 Automation

Automation 是保存好的自动化任务。每次运行时，Grok 都会使用同一组指令和当时能够获取的新数据，建立一段新的任务对话并保存结果。

| 你的目标 | 应选择的触发方式 | 套餐边界 |
|---|---|---|
| 指定时间运行一次 | One time / 一次 | xAI 官方说明向所有用户开放 |
| 每天、工作日、每周、每月或每年重复运行 | Schedule / 定时计划 | xAI 官方说明向所有用户开放 |
| 收到符合发件人、收件人或主题条件的邮件后运行 | Email trigger / 邮件触发器 | 包含在 SuperGrok 中 |
| 创建后立即检查指令是否有效 | `Run now` | 用于测试，不替代正式触发条件 |

如果还不能确定，先用“一次”或“每天”的定时任务。如果当前任务不需要读取邮件，就不要连接邮箱。

## 开始前准备四项内容

创建任务前，先写清楚下面四项：

1. **任务结果。**例如“列出 3 条 xAI 官方更新”，不要只写“帮我看看新闻”。
2. **信息范围。**说明允许访问的网站、文件或连接器。
3. **输出格式。**说明需要标题、日期、来源链接，还是表格和待办事项。
4. **触发条件。**确定运行一次、定期运行，还是收到指定邮件后运行。

任务越具体，越容易判断结果是否正确。Automation 不是“设置后一定正确”的保证；第一次保存后仍然需要手动测试。

## 第一步：进入 Automations 页面

1. 使用准备创建任务的 Grok 账号登录 [grok.com](https://grok.com)。
2. 打开 [grok.com/automations](https://grok.com/automations)。
3. 选择创建新 Automation，或者从页面提供的模板开始。
4. 如果页面只显示登录或注册入口，先完成登录，再重新打开 Automations 页面。

xAI 同时支持从普通聊天创建 Automation。你可以在聊天中直接要求 Grok 按某个时间重复执行任务；为了便于第一次核对全部设置，本文建议从 Automations 页面开始。

> **界面提示：**按钮名称和排列可能随 Web、iOS、Android 版本变化。无论界面如何调整，都应核对任务名称、指令、触发方式、时区和通知这五项。

## 第二步：填写任务名称和指令

任务名称用于日后识别，不应写入密码、订单号或其他敏感信息。名称可以写成“每周 xAI 更新摘要”或“工作日待办整理”。

指令应按“信息来源、任务动作、输出格式、限制条件”排列。例如：

> **示例指令**
>
> 只查看 xAI 官方新闻页。
>
> 找出最近发布的 3 条 Grok 消费端更新。
>
> 按发布时间从新到旧列出标题、发布日期、两句话摘要和官方链接。
>
> 如果没有新的官方更新，请明确写出“本次未发现新内容”，不要引用其他网站。

这段指令有四个好处：来源明确、数量明确、格式明确，也规定了没有结果时应该怎样回答。

不要在自动任务中填写账号密码、验证码、恢复码、完整卡号或公开后可能造成损失的凭证。

## 第三步：选择触发方式

### A. 创建定时任务

xAI 官方发布页列出的定时选项包括：

- 运行一次；
- 每天；
- 每个工作日；
- 每周；
- 每月；
- 每年。

设置时按以下顺序检查：

1. 选择运行频率。
2. 选择日期和时间。
3. 确认页面使用的时区与自己当前所在地一致。
4. 再次阅读下一次运行时间，确认没有跨日或相差 12 小时。

如果只是测试，先设置一次性任务，或者保存后使用 `Run now`。不要连续创建多个内容相同的任务，否则稍后可能收到多份重复结果。

### B. 创建邮件触发器

邮件触发器会监测已授权邮箱。当新邮件符合指定条件时，Grok 会把该邮件作为上下文执行任务。官方列出的筛选条件包括发件人、收件人和邮件主题。

启用前按以下顺序操作：

1. 确认当前 Grok 账号具有有效 SuperGrok 订阅。
2. 在 Grok 官方界面选择 Gmail 或 Outlook 等对应连接器。
3. 进入邮箱服务商自己的授权页面。
4. 核对申请的权限和当前登录的邮箱账号。
5. 只在确认权限范围后完成授权。
6. 返回 Automation，设置发件人、收件人或主题条件。

不要把邮箱密码、验证码或恢复码发送给客服或任何第三方。OAuth 授权是由邮箱服务商确认访问权限，不等于把邮箱密码交给 Grok。

如果页面没有邮件触发器，先确认当前账号订阅状态和应用版本。**不要因为入口暂时不可见就重复购买会员。**

## 第四步：按需添加文件、连接器、技能和模式

xAI 官方说明，Automation 的指令可以附加文件，也可以加入连接器、技能并选择运行模式。

| 设置项 | 什么时候需要 | 第一次测试的建议 |
|---|---|---|
| 文件 | 每次运行都要参考同一份资料 | 只上传不含敏感信息的测试文件 |
| 连接器 | 需要读取邮箱、日历或云端文件 | 先不添加；基础任务成功后再逐个授权 |
| 技能 | 需要固定的专用处理方式 | 没有明确用途时保持为空 |
| 模式 | 需要指定 Grok 的处理方式 | 不确定时保留界面默认值 |

一次只增加一个外部数据源。这样，如果任务失败，你可以判断问题来自指令、触发条件，还是新增加的连接器。

## 第五步：设置通知并保存

Automation 每次运行后，可以通过应用通知、邮件通知、两者同时通知，或不主动通知。选择方式时考虑结果的紧急程度：

- 需要及时处理的结果，可以开启应用通知；
- 不常打开 Grok 时，可以考虑邮件通知；
- 结果仅用于定期归档时，可以关闭通知，之后查看运行历史。

保存前，完整核对以下内容：

- [ ] 名称能准确说明任务用途；
- [ ] 指令包含来源、动作和输出格式；
- [ ] 日期、时间和时区正确；
- [ ] 邮件筛选条件不会匹配大量无关邮件；
- [ ] 连接器权限与任务需要一致；
- [ ] 通知方式不会造成重复提醒。

确认后保存任务。保存成功只说明任务已经建立，不说明指令和连接器一定可以正常执行。

## 第六步：用 Run now 完成第一次测试

1. 在刚保存的 Automation 中选择 `Run now`。
2. 等待本次运行结束。
3. 打开运行历史中的最新记录。
4. 阅读完整对话，而不是只看通知摘要。
5. 检查来源、日期、数量和输出格式是否符合指令。

根据结果处理：

| 测试结果 | 下一步 |
|---|---|
| 结果正确，来源和格式符合要求 | 保留任务，等待下一次计划运行 |
| 内容正确，但格式不稳定 | 编辑指令，增加明确的输出格式后再测试一次 |
| 引用了不需要的网站 | 在指令中写明允许来源和禁止来源 |
| 没有读取连接器内容 | 检查连接器是否已授权给当前 Grok 账号 |
| 运行失败并显示报错 | 保存报错文字和时间，停止重复运行并检查任务详情 |
| 一直处于运行中 | 不要反复点击 Run now；等待状态变化后再判断 |

只有这一步成功，才适合依赖后续计划运行。

## 第七步：查看历史并继续处理结果

xAI 官方说明，每次 Automation 运行都会建立一段完整对话，并保存到运行历史中。

打开某次运行后，你可以：

- 阅读完整结果；
- 查看本次使用的实际上下文；
- 在原对话中继续追问；
- 比较不同日期的执行结果；
- 根据失败记录修改任务指令。

如果通知内容不完整，应以运行历史中的完整对话为准。

## 第八步：编辑、暂停、恢复或删除任务

xAI 官方确认，已创建的 Automation 可以编辑、暂停、恢复和删除。

- **编辑：**修改指令、时间、触发条件或通知后，再执行一次 `Run now`。
- **暂停：**暂时停止未来运行，同时保留任务设置。
- **恢复：**重新启用已暂停任务，并检查下一次运行时间。
- **删除：**确定不再需要该任务时删除。删除前先保存仍需使用的结果。

当外出、休假或暂时不需要任务时，优先暂停，而不是创建第二个相同任务。

## 常见问题排查顺序

| 问题 | 先检查什么 | 仍未解决时 |
|---|---|---|
| 没有按时运行 | 任务是否启用、时间和时区、下一次运行时间 | 使用 Run now 测试并保存报错 |
| 收到重复结果 | 是否创建了多个相同任务，通知是否同时开启两种渠道 | 暂停重复任务，只保留一项 |
| 邮件没有触发 | SuperGrok 状态、邮箱连接器、发件人/主题条件 | 重新核对授权账号和筛选条件 |
| 结果缺少最新信息 | 指令是否允许访问当前网页或连接器 | 指定官方来源和日期范围 |
| Run now 失败 | 运行详情中的原始报错、文件和连接器状态 | 向 xAI 报告问题并提供脱敏证据 |
| 看不到 Automations 入口 | 当前平台版本、登录状态和应用更新 | 优先在 grok.com/automations 核对 |

联系 xAI 支持时，可以提供账号邮箱、使用平台、浏览器或系统、任务名称、运行时间、原始报错和脱敏截图。不要提交密码、验证码、恢复码或不必要的邮箱正文。

## SuperGrok 与充值边界

定时 Automations 不应被写成 SuperGrok 专属功能。只有当你明确需要邮件触发器，并且确认当前账号没有有效订阅、没有待处理交易时，才需要考虑 SuperGrok。

如果没有合适的海外付款方式，可以查看 [ChongGrok SuperGrok 实时方案](https://chonggrok.com/supergrok)。ChongGrok 使用用户自己的 Grok 账号完成会员订阅协助，不需要登录密码；Grok User ID 仍是敏感账号标识，只应通过确认的核销流程提交。任何线上服务都不是零风险，也不能保证某项新功能立即向所有账号开放。

## 隐私与安全边界

- 连接邮箱或云盘前，先阅读授权页面列出的权限。
- 自动化指令中不要长期保存密码、验证码、恢复码和支付信息。
- 邮件触发器可能把符合条件的邮件内容交给 Grok 处理，应缩小筛选范围。
- 不再使用连接器时，应在对应账号设置中撤销授权。
- 本文讨论 Grok 消费端 Automations，不提供 API 额度或 API 自动化教程。
- ChongGrok 与 xAI、X、Google、Microsoft 不存在隶属、授权或官方合作关系。
